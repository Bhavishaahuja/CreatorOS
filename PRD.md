# Product Requirements Document
## CreatorOS: AI-Powered Content Planning for Instagram Creators
 
**Version:** 1.0
**Status:** MVP
**Last updated:** June 2026
 
---
 
## Problem Statement
 
Emerging Instagram creators, those with 1k–50k followers who are past the learning curve but not yet full-time, lose hours every week deciding what to post and when. The problem is not that they lack ideas. It is that no existing tool accounts for their real schedule. Tools like Apaya and Notion AI generate generic content calendars with no awareness of a full-time job, brand events, or personal commitments. CreatorOS connects to your Google Calendar and generates niche-specific content ideas built around your actual availability, turning hours of planning into minutes with a strategy that fits your real life, not a hypothetical one.
 
---
 
## Target User
 
Instagram creators with 1k–50k followers who:
- Are past the beginner stage and know how to make content
- Have a full-time job or studies running alongside their content
- Post inconsistently, not because they lack ideas but because life gets in the way
- Currently plan in their head or not at all
- Want to grow but struggle to maintain a consistent posting schedule
**Who this is NOT for:**
- Full-time creators with a dedicated team or manager
- Complete beginners still figuring out how to use Instagram
- Creators who are deliberately spontaneous and resistant to any structure
---
 
## User Stories
 
1. As a creator with a full-time job, I want CreatorOS to see my work schedule so that it only suggests shoot days when I am actually free.
2. As a creator, I want to approve or reject AI-generated content ideas so that my feed stays true to my voice and brand, not a generic template.
3. As a creator, I want to add my own content ideas alongside AI suggestions so that I can combine my instincts with the structure the tool provides.
4. As a creator, I want a calendar that shows me exactly when to shoot, edit, and post so that I never scramble at the last minute or miss a deadline.
5. As a creator, I want content ideas that are specific to my niche and audience so that the suggestions feel relevant, not copy-pasted from a generic playbook.
6. As a creator, I want the onboarding to be quick and conversational so that I understand the value of the tool before I have to commit to connecting my calendar.
7. As a creator, I want to be able to regenerate suggestions if I reject most of them so that I am not stuck with a bad batch.

## In Scope: MVP
 
| Feature | Description |
|---|---|
| Onboarding flow | 5-question conversational setup capturing content type, audience, brand vs personal, goal, and posting frequency |
| Google Calendar integration | OAuth connection to read events and identify free shooting days for the next 4 weeks |
| Manual availability fallback | Checkbox-based day picker if user skips or cannot connect Google Calendar |
| AI content suggestions | 10 niche-specific ideas per cycle generated by Claude API, personalised to user profile and available days |
| Approval flow | Card-based UI to approve or reject each idea, with ability to add custom ideas and deadlines |
| Regenerate suggestions | Option to generate 10 more ideas, informed by what was rejected |
| Content calendar | Auto-generated calendar with shoot, edit, and post deadlines for every approved idea |
| Prompt versioning | Every AI suggestion is tagged with the prompt version that generated it |
 
**Platform:** Instagram only
**Deployment:** Web (mobile-responsive)
 
---
 
## Out of Scope: MVP
 
| Feature | Reason excluded |
|---|---|
| Multi-platform support (TikTok, YouTube) | Each platform has distinct API requirements and content formats. Adding multiple platforms in MVP dilutes focus and increases build time without validating the core loop first. |
| Auto-scheduling and posting | Requires integration with Buffer or Later, app store approval, and additional OAuth scopes. High complexity, low priority until core planning loop is validated. |
| Analytics and performance tracking | Instagram Graph API requires app review and specific permissions. Also requires users to have posting history in the tool, which is not possible in MVP. |
| Brand kit parsing | Parsing PDFs and images for brand assets adds significant complexity. Can be approximated in MVP by capturing tone-of-voice words during onboarding. |
| Self-learning and personalisation | Requires sufficient user history and embedding infrastructure. Planned for Phase 2 once core product has real usage data. |
| Team and agency accounts | Multi-account architecture is a significant rebuild. Not the target user for MVP. |
| Mobile app (iOS/Android) | Web-responsive covers the use case for MVP. Native app adds distribution complexity with no added value at this stage. |

## Success Metrics
 
| Metric | Definition | Target | Why It Matters |
|---|---|---|---|
| Onboarding completion rate | % of users who complete all 5 onboarding steps | > 70% | If users drop off during onboarding, the value proposition or the flow itself is not clear enough |
| AI suggestion approval rate | % of AI-generated ideas a user approves per session | > 40% | The single best signal that the AI is generating relevant, personalised ideas. Below 40% means the prompt needs reworking. |
| Time to first calendar | Time from starting onboarding to completing a content calendar | < 10 minutes | Measures how quickly the product delivers its core value. Longer than 10 mins signals unnecessary friction. |
| Week 2 retention | % of users who return and generate a new content plan the following week | > 50% | **North star metric.** A user who comes back a second week has found real value. This is the strongest signal of product-market fit. |

## Open Questions
 
1. **Approval rate baseline:** We do not yet know what a realistic approval rate looks like before RAG is implemented. Need at least 20 real sessions to establish a baseline before optimising the prompt.
2. **Calendar parsing accuracy:** How reliably can we infer "free to shoot" from raw calendar events? A meeting titled "lunch" is free. A meeting titled "dentist" is not. Does a rule-based parser work or do we need AI classification?
3. **Token refresh edge case:** Google OAuth access tokens expire after 1 hour. If a user leaves the app mid-session and returns, we need to handle silent refresh gracefully. What is the fallback if refresh fails?
4. **Rejection without explanation:** Currently rejections are binary. Should we prompt users to tag why they rejected (wrong format, wrong topic, already done it)? This data would significantly improve future suggestions but adds friction to the flow.
5. **Cold start problem:** On a user's first session, there is no approval history to inform suggestions. How do we make the first batch feel personalised enough to earn trust before we have any data on their preferences?
6. **Minimum viable calendar:** If a user only approves 2 out of 10 ideas, is a 2-item calendar still useful? What is the minimum number of approved ideas before we generate the calendar?
